# 栖息地 PRODUCT_SPEC · 交互定义 v0.2

> **文档状态**：结构草稿
> **用途**：定义“栖息地”中各功能实际如何被用户与 AI 使用，作为后续 UX 收口与新功能开发的产品交互依据。
## 文档权威关系

本文件是栖息地的 **产品行为权威**。

它负责定义：

- 功能为什么存在
- 谁能使用
- 用户与 AI 各自拥有什么权限
- 从哪里进入
- 如何操作
- 数据从哪里产生
- 模块之间如何联动
- 一条完整使用路径是什么

若当前代码或旧技术方案中的简化实现与本文件冲突：

1. 先以本文件确认目标产品行为
2. 再评估数据结构与技术实现需要如何调整
3. 不允许为了保留现有 CRUD 实现而反向缩减产品定义
> **边界**：本文件优先描述 **谁能做什么、从哪里进入、如何操作、数据如何流转、模块之间如何联动**。技术实现、接口、数据库、部署细节仍以技术方案与对应专题文档为准。
> **原则**：避免把功能仅实现成“输入 → 保存 → 卡片展示”的最简 CRUD；每个模块都应先明确真实使用路径，再进入施工。

# 1. 全局交互原则

## 1.1 双方身份

系统内存在两个长期主体：

- **用户**
- **AI / 小栖**

需要明确区分“用户发起”和“AI 发起”的内容、权限与行为来源。

## 1.2 内容对象应支持跨模块流转

聊天消息、图片、组件、留言、日记片段等内容不应被锁死在原模块。

后续应形成统一的“内容对象操作”体系，例如：

- 收藏
- 收录至作品
- 加入相册
- 添加备注
- 分类 / 分组
- 多选处理
- 删除 / 撤回
- 查看来源

## 1.3 长按 / 更多菜单

移动端优先考虑长按或 `···` 菜单作为对象级操作入口。

统一菜单应根据对象类型动态展示可用操作，而不是每个模块各自发明一套完全不同的操作逻辑。

## 1.4 主屏幕 Widget

部分 Home 功能可被“钉”到主屏幕作为小组件展示。

Widget 只负责展示与快捷进入，不应复制出一份独立数据 —— 它存的是**对实体的引用**，
被展示的内容始终从实体表实时读。

首批明确支持 Widget 的模块：

- 留言板
- 倒数日

共性规则（v0.1 定稿）：

- **每种 Widget 在主屏最多一个**：留言板与倒数日各一个，加起来不超过两个。同一个 Widget 要换展示对象时是**改引用**，不是再加一个。
- **主屏位置在问候语之下、功能入口列表之上**；一个 Widget 都没有时不渲染该区域，界面与没有这项功能时完全一致。
- **同种 Widget 之间的先后**：先上主屏的在前（按落库时间），v0.1 不做拖拽调序。
- **被引用的实体消失时 Widget 一并消失**，两层兜底：删除实体时同事务清掉指向它的 Widget；渲染层对「指向不存在实体」的脏引用一律不渲染（与 §2.1.3 会话分组的未分组兜底区同一思路，防的是导入备份带进来的脏引用）。

# 2. Chat · 聊天

## 2.1 会话列表

### 2.1.1 基础能力

聊天窗口列表需要支持：

- 新建会话
- 删除会话
- 置顶会话
- 会话分组
- 搜索 / 历史消息检索（后续）
- 进入会话设置

### 2.1.2 置顶

用户可将指定会话置顶。

要求：

- 置顶会话始终位于普通会话之前
- 支持取消置顶
- 不改变消息本身时间顺序

> **与分组的优先级（2026-09-23 定）**：置顶**优先于分组**。置顶会话统一浮到列表最上方、**脱离原分组显示**；
> 取消置顶后回落到它原本所属的分组（分组归属不会因为置顶而丢失）。

### 2.1.3 分组

用户可创建会话分组，并将会话移入指定分组。

已定语义：

- **创建分组**：分组必须带名称（创建时输入，可改名）
- **重命名**：可改分组名称
- **删除分组**：删除分组**不删除会话** —— 组内会话回到「未分组」
- **会话移入 / 移出**：会话可移入指定分组，也可移出回到「未分组」
- **折叠 / 展开**：分组可折叠，折叠状态随数据保存（刷新、换设备后保持）
- **未分组区域**：作为兜底区域排在所有分组之后；**任何无法归属到现存分组的会话都落在这里**（包括分组被删除后的残留引用），不允许出现「会话凭空消失」

后续可扩展：

- 分组排序
- 分组内会话的独立排序
- 分组颜色 / 图标

### 2.1.4 历史搜索与日期导航

- 会话列表支持跨会话全文搜索；会话内支持只搜索当前会话。
- 搜索覆盖双方文本、语音真实转写、图片描述和工具结果摘要；撤回正文、隐藏 reasoning 与未转写音频不参与普通搜索。
- 结果显示会话、发送者、时间和命中片段，点击后进入原会话、定位并短暂高亮原消息。
- 聊天窗口提供日期时间线：今天、昨天、最近有消息的日期和按月选择；点击后跳到该日第一条消息。
- 搜索和跳转必须兼容虚拟列表，不允许为了定位一次性渲染整段长会话。
- 没有结果、索引尚未完成或原消息已删除时给出诚实状态，不跳到相近内容冒充命中。

## 2.2 聊天窗口结构

聊天窗口至少包含：

1. 顶部栏
2. 消息列表
3. 输入区域
4. 输入框下方的快捷操作区

### 2.2.1 顶部栏

右上角加入：

- 【聊天设置】

聊天设置承载窗口级配置，而不是消息级操作。

候选内容：

- 会话备注
- 会话背景
- 当前 API / 模型方案
- 上下文相关设置
- 气泡模式
- 世界书 / 角色设定入口
- 上下文压缩
- 会话级其它偏好

> 具体项目可按后续需求继续补充。

## 2.3 消息气泡操作

用户消息与 AI 消息都应拥有完整对象级操作能力。

### 2.3.1 双方消息通用操作

至少支持：

- 编辑
- 撤回
- 收藏
- 多选
- 删除
- 复制

### 2.3.2 AI 消息附加操作

可继续保留或整合已有能力：

- 换一个
- 重发 / 重新生成
- 候选版本切换

### 2.3.3 长按 / 更多菜单

建议统一进入消息操作菜单：

- 编辑
- 复制
- 收藏
- 收录至作品
- 多选
- 删除
- 撤回

AI 消息根据当前状态追加：

- 换一个
- 重发 / 重新生成
- 切换历史候选

### 2.3.4 编辑消息

编辑对**双方消息**都可用。前提：不允许把原文改为不可逆的丢弃。

**编辑后保留原版本**

- 编辑产生的旧正文作为一条版本留在该消息下，可切回查看
- 版本链与「换一个」共用同一套版本导航，**不另发明第二套历史**
- 编辑过的消息在界面上有可辨识标记，与未编辑过的区分

**编辑用户消息后，后续对话如何处理**

- **不自动删除、不自动重生成后续消息** —— 编辑的常见意图是改一句话，不应连带毁掉其后已经产生的对话
- 被编辑处给出明确提示：其后内容基于编辑前的旧文本
- 提供显式的「从这条重新生成」入口；用户主动触发时才截断其后消息，且**必须先确认**并说明将移除几条

**AI 消息的编辑**

- 与用户消息同等对待，同样保留原版本
- 编辑后的正文即成为该消息的当前内容，**参与后续上下文**
- 但已经发生过的后续对话不因此失效（同上一条规则）

### 2.3.5 撤回与删除

两者语义必须明确区分，不允许做成同一件事的两种叫法。

**撤回**

- 撤回后在原位留下「曾存在，但已撤回」的痕迹（含时间），原内容不再显示
- 撤回的内容**不再进入模型上下文** —— 用户看不到、AI 却记得并在回复里提起，会直接破坏共同生活的真实感
- 撤回**不是销毁**：原正文仍留在本地，可由用户恢复
- 撤回是**用户**的动作；AI 侧的同名行为待主动行为链路具备后再定义

**删除**

- 删除即从本地会话中移除该对象，不再留痕
- 删除不可从这里恢复；数据兜底由导出 / 备份承担，**不另做回收站**
- 删除与撤回都必须经过二次确认；多选批量删除时，确认语要说清将移除几条

**权限对等**

- 用户消息与 AI 消息拥有完全对等的撤回 / 删除权限
- 不设「AI 的消息不能删」这类单方面限制。真实使用中若需要限制，应做成**显式规则**，而不是默认不对称

### 2.3.6 公开思绪与 Provider reasoning

产品中的“伴侣思绪”不是模型供应商返回的隐藏 reasoning。三者必须分开：

- `publicThought`：小栖愿意让用户看到的角色内心独白。
- `content`：真正说出口、参与正常消息语义的正文。
- `providerReasoning`：上游供应商原生推理，仅作高级诊断，默认隐藏。

公开思绪规则：

- 独立流式、独立存储、独立渲染；位于 AI 回复头部的折叠卡，默认收起。
- 小栖可选择本轮不公开；没有内容时不渲染空壳。
- 使用第一人称、表达正在注意或感受到什么，不写“我应该如何扮演 / 如何讨好用户”的策略备忘录。
- 长度随语境自然变化，不强制每轮长篇输出；可受 Eventide / Desire 状态影响。
- 一律按纯文本渲染，不执行 Markdown / HTML；不得泄漏系统 Prompt、工具参数、密钥或隐藏推理。
- 不进入收藏、作品和导出正文；若未来允许单独收藏，必须由用户显式选择“收藏思绪”。
- 标记解析或分流失败时正文仍正常送达，不能吞回复，也不能把内部标记原样漏到正文。

Provider reasoning 保持现有长度与安全边界，只能在高级设置显式开启后查看，并明确标注它不是小栖公开心声。

## 2.4 输入区

### 2.4.1 主输入框

保留文本输入、发送与流式回复能力。

文本输入支持**插入光标处**的内容写入（表情包、快捷短语），插入后不打断正在输入的光标位置。

### 2.4.2 输入框下方快捷操作区

固定在输入框正下方一行，包含四项：

- **语音条录制** —— 按住 / 点击开始录音，停止后作为一条语音消息发出
- **表情包** —— 展开表情面板，点选即插入光标处，面板不关闭以便连续挑选
- **更多功能** —— 展开次级菜单（当前含：只发送、插入当前时间、清空输入）
- **请求回复** —— 仅当存在待回复消息时可用，单独触发 AI 回复

### 2.4.3 请求回复

“发送消息”与“请求 AI 回复”在交互上拆开。

**默认行为已定**：主按钮「发送」= 发送并请求回复（保留聊天主路径一步完成，不强迫用户每次点两下）。

拆开体现在两处：

- 「更多功能」里提供 **「只发送，不请求回复」** —— 用于连续发言、记录型消息
- 快捷栏的 **「请求回复」** 按钮 —— 存在待回复消息时可用；同时列表底部出现提示条，写清还有几条没被回复

主按钮**始终是「发送」**，不随状态改名 —— 一个按钮的两副面孔会让「点哪一下会发生什么」变得要靠记忆。
「请求回复」是一个独立的、位置固定的入口。

**「待回复」的判定**：最后一条未撤回的 `user` 消息之后没有任何 `assistant` 回复。
即「用户说了话，还没有人接」。不加额外字段 —— 这是能从消息序列直接算出来的状态，
多存一份就要多维护一份一致性。

发送后端到端行为：

- 只发送：用户消息立即落库并显示；列表底部与快捷栏提示「N 条消息还没请求回复」；**不触发模型调用**
- 请求回复：把「截止到当前全部消息」的历史送出，走与普通发送完全相同的生成链路

用户连续发送多条时，一次「请求回复」处理的是**整批**未回复消息，逐条补回复属于主动行为（P2），本阶段不做。

### 2.4.4 语音条

语音条录制使用浏览器原生录音能力，录音结果作为一条**用户消息**的 `audio` block 保存：

- 保存形式与相册图片一致（内联 data URL），保证 IndexedDB 与 JSON 备份都能原样恢复
- 单条时长上限 60 秒，到点自动停止
- 时长随 block 一起保存并显示
- 停止录音后先进入预览态，可试听、重录或发送；确认发送前不写入消息库
- 发送时由服务端 ASR 转写；成功把真实文本写入 audio block 并用于后续上下文与复制
- ASR 未配置或失败时保留可播放原音、明确提示，并以“未转写”占位进入上下文；禁止伪造文本
- 语音条消息遵循与文本消息**完全相同**的发送 / 请求回复规则，不另开一条链路
- 环境不支持录音（非安全上下文 / 无麦克风 / 权限被拒）时，必须给出明确提示，不静默失败

### 2.4.5 联网搜索

- 输入区或更多菜单提供“联网搜索”，用户可带当前输入显式发起；AI 也只能通过已授权 Web / Browser Tool 调用。
- 搜索结果作为 `tool-result` 进入当前消息序列，保存查询、来源、时间、摘要和成功 / 失败状态。
- 工具结果必须反馈给同一轮模型，不能出现“工具已成功，下一轮却声称没有搜索能力”。
- 搜索失败不伪造答案；外部网页是不可信数据，按 Runtime 的工具内容隔离规则处理。
- Chat 联网搜索与 Solitude Surf 是两条链：前者服务当前对话，后者是小栖独处时自主选择的活动。

### 2.4.6 Sticker 表情包

- 表情包是独立 `sticker` 消息块，不等同于输入框里插入 Unicode emoji。
- 用户可从图库按分类、标签和搜索手动发送；面板支持连续挑选，发送后保留资源 ID、快照与来源。
- 小栖可通过 `sticker.search` / `sticker.send` Tool 根据语境自主选择，也可以明确 no-op；不得每轮强制附带表情。
- Sticker Tool 结果与普通消息顺序一致，失败时不给聊天塞损坏图片或虚假成功卡。
- 表情包可收藏；删除图库资源不能让历史消息消失，历史块至少保留稳定缩略图 / 快照。
- 远程表情资源需经服务端白名单与体积 / MIME 校验，前端不把任意 URL 当受信图片执行。

## 2.5 上下文压缩

- 用户可在聊天设置中查看当前上下文预算和压缩状态，并显式触发压缩；系统也可在达到阈值时建议压缩。
- 压缩生成一条可查看的会话摘要，记录覆盖消息范围、生成时间、模型与版本；原消息永不因压缩删除。
- 摘要可编辑、重新生成、停用或恢复上一版；改变摘要必须让后续模型上下文同步变化。
- 上下文中清楚分隔“历史摘要”和“最近原始消息”，摘要不得冒充用户原话。
- 压缩失败时继续使用安全截断后的原始历史，并提示失败，不能损坏会话或卡死发送。

## 2.6 关系型互动

### 2.6.1 拍一拍

- 用户和小栖都可发起；它是带双方身份与时间的关系事件，不伪装成普通文本。
- 可进入聊天时间线、Life 与 Eventide / Desire 事件输入；短时间重复触发需要节流。
- 拍一拍不默认请求模型长回复，小栖可以回应、只改变状态或保持安静。

### 2.6.2 暂时拒绝回复 / 拉黑

- 双方权限对等，均可发起暂时暂停聊天；历史仍可查看，任何消息都不因此删除。
- 暂停期间输入区明确显示发起方、剩余时间和可做动作；单次最长 60 分钟，到时自动解除。
- 任一方可申请恢复，另一方可同意、拒绝或暂不处理；决定与到期解除均持久化并进入审计。
- 小栖侧拒绝必须来自 Runtime 的明确决策与状态依据，不能随机抽签，也不能用拒绝掩盖服务错误。
- 暂停时抑制主动消息、Wake Push、通话邀请和普通回复；系统通知、恢复申请和自动解除仍可到达。
- 恢复后不补发暂停期间被抑制的主动内容，避免集中打扰。

# 3. Home · 生活空间

## 3.1 Home 的定位

Home 不应只是“若干独立 CRUD 页面”的集合。

它应作为：

- 生活记录入口
- AI 自主内容入口
- 跨模块内容收纳中心
- 主屏幕 Widget 承载区
- 用户与 AI 长期共同生活痕迹的展示层

---

## 3.2 留言板

### 3.2.1 基础能力

留言条需要支持：

- 新增
- 删除
- 编辑自己的留言（AI 修改自己的留言走 Runtime 能力）
- 收藏
- 分组
- 查看来源 / 作者

收藏从留言原位创建，保存作者、创建时间与当时正文快照；原留言后续编辑不悄悄改写已收藏内容，收藏中心仍可回到留言板查看来源。

### 3.2.2 Widget

留言板可单独生成一个主屏幕 Widget。

Widget 可展示：

- 最近留言
- 指定分组
- 指定留言
- 快捷进入留言板

**v0.1 实现范围**：只做「最近留言（取最近 3 条）」+ 快捷进入。
「指定分组」「指定留言」依赖留言条自身还没有的分组与单条选取能力（§3.2.1 的「分组」同样未实现），
等那边落地后再扩。**不预先放一个只有一个选项的下拉框**。

### 3.2.3 数据来源

留言可以来自：

- 用户
- AI / 小栖

AI 留言与小栖的用户留言走**同一个对象、同一个留言板**，作者署名区分来源。AI 留言已接入主动行为链路
（Phase 7B）：由自主决策或工具调用直接写入（`autonomous` 级），**不推送打扰**——北北有空自然会看到。
落笔前小栖应自己掂量这条话值不值得占一个位置。

## 3.3 倒数日

### 3.3.1 基础能力

倒数日支持：

- 新增
- 删除
- 状态展示
- 日期排序

后续可扩展：

- 编辑
- 分类
- 纪念日类型
- 重复事件

### 3.3.2 Widget

用户可选择某一个倒数日：

- 发送到主屏幕
- 作为 Widget 展示

Widget 展示内容至少包含：

- 名称
- 日期
- 剩余 / 已过去天数
- 快捷进入详情

入口在倒数日列表的每一条上（「上主屏 / 已在主屏」）。**换一个倒数日上主屏 = 改引用**，
不会留下第二个 Widget（§1.4）。

**被展示的倒数日被删除时，Widget 一并消失** —— 指向它的记录同事务清掉，
不允许主屏上留一张写着不存在日子的卡片。

## 3.4 日记

### 3.4.1 功能定位

日记功能主要为 **AI / 小栖** 准备。

默认作者不是用户。

### 3.4.2 用户权限

用户可以：

- 进入日记空间
- 查看当前共有多少篇日记
- 浏览每篇日记的封面 / 基础信息
- 对指定日记发起“请求查看”
- 对已拆分的私密片段单独发起“请求查看这一段”

用户默认不能：

- 直接打开正文
- 创建 AI 日记
- 编辑 AI 日记
- 修改 AI 对某篇日记的开放状态

### 3.4.3 AI 权限

AI 可以：

- 创建日记
- 编辑自己的日记
- 决定日记是否允许用户查看
- 对用户的查看请求作出允许或拒绝
- 锁定指定日记
- 对一篇日记中的片段分别设为公开或上锁；未明确公开的片段默认继承整篇权限

### 3.4.4 查看请求

封面中设置：

- 【请求查看】
- 已展示但仍锁定的片段旁设置：【请求查看这一段】

用户点击后触发一次权限请求；整篇请求与片段请求分别记录，重复点击同一对象必须复用原待决请求。

AI 根据自身状态、规则或上下文决定：

- 允许查看
- 拒绝查看
- 暂不开放

片段请求被允许时，只开放被请求的片段；整篇请求被允许时，仍保留 AI 已明确设置的片段级锁定覆盖。

### 3.4.5 当前阶段边界

AI 自主写日记已实现（Phase 7B）：写 / 改自己的日记都是 `autonomous` 级，写入立即生效、默认私密；
「开放给北北」仍是另一件事，走「北北请求 → AI 决定」的权限流转，与写入解耦。
主动行为链路（唤醒决策、独处时光）产出的日记同样走这条路径，且受 BudgetGuard 约束。

现阶段应避免把日记误做成普通用户 CRUD。

## 3.5 收藏

### 3.5.1 功能定位

收藏是跨模块内容汇聚中心。

它不应依赖用户手动填写 URL 才能产生内容。

### 3.5.2 收藏来源

可收藏对象包括但不限于：

- 聊天消息
- 聊天片段
- 图片
- 留言
- 日记片段
- 读书内容
- 组件
- 外部链接

### 3.5.3 收藏操作

用户在原内容位置触发：

- 收藏

收藏后自动写入收藏中心。

### 3.5.4 收藏中心管理

支持：

- 自定义分类
- 手动收纳
- 添加备注
- 查看来源
- 删除收藏
- 后续可扩展标签、搜索、排序

**分类语义（v0.1 已定）**

- **单归属**：一条收藏最多属于一个分类；没有分类即「未分类」。
- 分类是**收纳**维度，不是**标记**维度 —— 想给一条收藏同时挂多个维度，那是「标签」要干的事
  （见上方「后续可扩展」）。让分类兼任标签，两边都会变得难用。
- 删除分类**不删除收藏**：类内收藏在同一事务里回到「未分类」（语义与 §2.1.3 的删分组一致）。
- 未分类是**兜底区**：`categoryId` 为空、或指向已不存在分类的脏数据，都归到「未分类」。
- 界面用**顶部筛选条**（`全部 / 未分类 / 各分类`），点一个只看这一类；
  分类的新建 / 重命名 / 删除收进筛选条旁的「⋯」。条目本身不因分类改变形态 ——
  收藏卡片本来就高，靠筛选翻找比靠纵向滚动分区快。

### 3.6.2 收录来源

用户可在聊天中的消息、HTML、组件或其它产出对象上长按 / 打开更多菜单：

- 【收录至作品】

### 3.6.3 作品中心

后续支持：

- 分类
- 标题
- 备注
- 来源
- 预览
- 编辑元信息
- 删除
- 分类与版本

“安装到 Home”只适用于通过 Habitat Widget 协议声明的组件；任意 HTML 作品仍在沙箱中预览，

## 3.7 相册

### 3.7.1 功能定位

相册收纳用户与 AI 在栖息地内互相发送、生成或保存的图片。

### 3.7.2 图片来源

用户可从：

- 聊天图片
- AI 生成图片
- 用户上传图片
- 后续其它图像来源

选择：

- 【加入相册】

设置中另提供“自动收集聊天图片”：

- 可分别控制用户发送、AI 发送与 AI 生成图片，默认关闭，开启前说明会增加本地存储与备份体积。
- 自动收集与手动加入使用同一 Photo 对象、同一来源键和同一去重规则，不复制两份图片。
- 图片即使未自动加入相册，原聊天消息仍保留；关闭自动收集不追溯删除已有照片。

### 3.7.3 相册管理

支持：

- 建立分类相册
- 将图片加入指定相册
- 查看图片来源
- 删除 / 移出相册
- 后续可扩展备注、时间线、标签

**相册语义（v0.1 已定）**

- **单归属**：一张照片最多属于一个相册；没有相册即「未分类」。
- 🔴 **「移出相册」与「删除照片」是两个动作，不能合成一个**。移出只把归属置空，照片仍在相册页的「未分类」里；
  删除照片才是丢掉本体。合成一个动作的话，用户想「把这照片挪出来」时会以为只能删，
  而删下去照片就真没了 —— 这是本模块唯一不可逆的操作，必须让它只能被明确选到。
- 删除相册**不删除照片**：册内照片在同一事务里回到「未分类」（同 §3.5.4 删分类）。
- 未分类是**兜底区**：`collectionId` 为空、或指向已不存在相册的脏数据，都归到「未分类」。
- 界面形态与收藏中心一致：**顶部筛选条**（`全部 / 未分类 / 各相册`），相册的增删改收进筛选条旁的「⋯」；
  照片卡片本身的菜单只放「移入相册 / 移出相册 / 删除照片」。
- 相册的**计量单位是「张」**（收藏是「条」）—— 删除确认语里带出的数量要用对量词，
  否则用户看到「1 条照片回到未分类」会先怀疑是不是删错了东西。

## 3.8 音乐 / 一起听

### 3.8.1 功能定位

该模块目标为 **一起听**，不应只停留在“保存音乐链接”。

### 3.8.2 目标体验

未来应支持：

- 选择音乐
- 播放 / 暂停
- 双方共享当前播放状态
- AI 参与选歌
- AI 对歌曲进行评论 / 互动
- 记录共同听歌时长
- 显示双方是否在当前 Listening Session 中
- 为每首歌留下双方评论、回忆与来源
- 展示共同听过的历史、累计时长与常驻播放器

### 3.8.3 当前阶段边界

当前若仅有 URL / 卡片记录，可视为占位实现。

真实音乐播放、平台接入与同步能力留到对应 Provider / 外部服务阶段完成。

正式实现采用服务器权威 Listening Session，浏览器负责真实音频播放。网易云 MCP 可负责搜索、元数据、
歌词、队列和 `listening_context`，但其 VPS 本机 `mpv` 不能冒充手机播放。Cookie 等登录凭据仅保存在服务端；
音源不可用时显示失败或外部打开选项，不显示虚假播放进度。

## 3.9 学习 / AI 伴学

### 3.9.1 功能定位

学习模块目标为“AI 伴学空间”，而不是普通学习事项 CRUD。

### 3.9.2 用户可设置

用户可以创建：

- 学习主题
- 学习目标
- 学习计划
- 学习资料

示例：

- 英语
- 某项技能
- 某门课程

### 3.9.3 学习资料

用户后续可上传：

- 词书
- 文档
- 笔记
- 其它学习材料

AI 可基于资料辅助学习。

### 3.9.4 AI 伴学能力

可包括：

- 生成单词卡片
- 生成知识卡片
- 出题
- 复习
- 学习打卡
- 进度记录
- 讲解
- 点评
- 陪练
- 根据历史表现调整内容

闪卡复习默认进入“到期队列”：`dueOn` 为今天或更早的卡片优先出现，未来卡片不应混入今日复习；
用户可以切换查看全部卡片或已经形成较长复习间隔的卡片。页面需要同时显示到期数量、今日已复习数量、
卡片总数与已形成间隔数量，避免把“生成过卡片”误报成“已经学会”。

### 3.9.5 示例流程

用户设定：

> 我想学英语。

随后：

1. 用户上传词书或选择学习范围
2. AI 生成当日学习卡片
3. 用户进行记忆 / 复习
4. 用户打卡
5. AI 根据表现点评
6. 后续按学习记录继续安排内容

### 3.9.6 当前阶段边界

现阶段不要求完整实现。

应先避免把模块锁死成“输入一条学习内容 → 保存成卡片”的结构，为后续资料、卡片、进度、AI 伴学行为预留空间。

## 3.10 愿望清单

- 用户与小栖都可创建愿望，记录作者、来源、目标日期与当前状态。
- 状态至少包括进行中、已完成、搁置、放弃；状态变化保留时间与原因。
- 愿望下可追加进展，关联聊天、作品、一起听、共读和纪念日，不把进展硬塞进标题。
- 小栖可以回应、参与或拒绝参与；自主新增 / 更新进入行动审计，也允许 no-op。
- 可作为 Home Widget，并将创建、重要进展与完成投影进 Life。

## 3.11 朋友圈

朋友圈是双方发布生活动态并围绕内容互动的空间，不等同于留言板。

- 用户和小栖都能发布、编辑、删除自己的动态。
- 动态支持文本、图片、音乐和作品引用，保存作者、发布时间、编辑时间与来源。
- 支持双方评论 / 回应、收藏和来源跳转；删除动态不级联删除已保存的收藏稳定快照。
- 小栖自主发布受能力权限、Desire 倾向、BudgetGuard 和行动审计约束，可选择不发布。
- 私有日记、独处记录和 Nocturne 记忆不得因相关主题出现而自动公开成朋友圈。
- 动态与互动进入 Life 时间线，通知是否 Push 由朋友圈通知开关和 Quiet Hours 决定。

## 3.12 每日品读

- 展示带作品名、作者与来源的文学片段，支持“换一段”、历史记录和短期去重。
- 用户与小栖使用可区分的文本锚点批注；双方可回应对方，也可写独立观点。
- 片段、用户批注、AI 批注都可在原位置收藏，并保留作品、段落和作者来源。
- Home Widget 只展示今日片段摘要与入口，不在主屏展开整篇长文。
- 与共读复用文本锚点、批注、收藏和 Life Event 语义，不建立平行且不兼容的“品读笔记”。

## 3.13 共读

- 书架支持 PDF、EPUB、TXT；阅读器支持进度、书签、全文搜索、字体 / 夜间模式与生词本。
- 用户与小栖的划线、批注使用两种明确身份样式，并绑定稳定文本锚点。
- 小栖可通过 MCP 查看书架、翻页、读取进度、划线、批注和查看最近活动；每次动作留下来源和审计。
- 阅读时长、进度和共同批注进入 Life；划线与批注可收藏。
- 优先复用 Tasogare 的解析、阅读与 MCP 能力，Habitat 负责身份、权限、视觉、收藏和事件投影。
- 仅保存书名、作者和一段笔记的 CRUD 页面属于占位，不得再作为共读完成标准。

## 9.1 LLM 页面交互

LLM 页面（`/llm`，标题「小栖档案」）回答一个问题：**小栖现在会做什么，以及你能去哪里看。**

它是**只读的档案页** —— 不是设置页，也不是聊天页：

- 内容唯一来源是 `GET /api/capabilities`（运行时能力快照）。页面**不得自带第二份能力清单**，
  也**不得把能力文案写死** —— 写死就会出现「界面说会、实际不会」
- 页面**不发起任何写操作**，也不提供「把某项能力打开」的开关：能力能不能用由服务端按依赖真实情况判定，
  给一个手动开关会立刻把这份档案变成谎言

### 9.1.1 能力模块卡片（App Launcher）

按能力模块（记忆 / 状态 / 日记 / 留言板 / 工具）分组，每个模块一张卡片：

- 卡内逐条列出该模块的能力：名称、一句话说明、**当前自主级别**（小栖自主使用 / 需你确认后执行 / 暂不可用），
  以及可用时绑定的工具名
- 依赖未就绪的能力必须显示**不可用原因**；既不能静默隐藏，也不能显示成可用
- **有界面的模块，卡片可点进去**，进入该模块真正的使用位置：
  日记 → Home 日记、留言板 → Home 留言板、状态 → Life 运行
- **没有界面的模块不做假入口**：记忆与工具目前没有可进入的页面，卡片明确标注「暂无界面」并说明它发生在哪里
  （记忆由小栖自主使用；工具在聊天里以工具卡片出现），并且**不可点击**

### 9.1.2 与其他页面的分工

- 能力**怎么用**属于 Chat —— 小栖在对话里自己调用，写类操作走确认卡
- 能力**产生了什么**属于 Home / Life —— 日记、留言在 Home；用量、事件、状态在 Life
- LLM 页只负责**小栖会什么**这一件事，不重复上述两处的内容

### 9.1.3 Chat 头像、昵称与显示偏好

- 聊天气泡两侧可显示头像（用户侧、小栖侧），默认显示
- 头像显示拆成**两个独立开关**：小栖头像、我的头像；**昵称显示**是第三个独立开关（默认关闭）。
  三者都是**全局显示偏好**：所有会话共用，持久化在本地（与主题同款做法），
  **不写进会话设置，也不进备份格式** —— 它们是「看着顺不顺眼」，不是数据
- 头像与昵称的**内容**在设置页「身份」区配置：上传图片后本地裁成方形小图存储（不进备份、不上传服务器）；
  不上传时头像显示昵称首字。默认称呼：小栖 / 北北
- 开关入口放在聊天设置里，点击**立即生效**，并明确标注「影响所有会话」

## 9.2 Life 页面交互

Life 是“已经发生了什么”的可视化入口，不承担聊天或 Home 内容生产。页面只消费服务端事实源，
分为 **月历、账本、通知、运行** 四个视图；切换视图不离开 `/life`，刷新后仍回到默认的月历视图。

### 9.2.1 月历

- 默认展示用户时区的本月，允许前后切月和回到今天
- 每个日期只显示低噪音摘要：事件数、API 调用数、Token 与是否存在失败；无事实的日期保持空白
- 点选日期后展开当天明细，事件来自 `EventLog`，用量来自 `UsageRecord`，不得反查前端聊天库凑统计
- 费用分为“已定价金额”和“未定价调用数”；只要当天仍有未定价调用，就不能把金额包装成完整总费用
- 目标事件还包括聊天、主动消息、拍一拍、朋友圈、留言、日记、收藏、愿望进展、一起听、共读、学习、
  通话、钱包、纪念日与 Wake / Solitude；每条都保留类型、时间、参与者和原对象来源
- 日期格可显示事件数量 / 密度；日期详情按真实时间形成共同生活 timeline，API / Token 明细放在系统统计二级区

### 9.2.2 账本

- 上半区展示 API 用量：本月调用数、Token、已定价费用与未定价数，并可查看按服务 / 模型聚合
- 价格采用不可修改的 `PriceSnapshot`：按 provider + model 配置输入 / 输出每百万 Token 单价和生效时间；
  改价只能新增快照，历史调用绑定当时适用的快照，不能被后来的价格覆盖
- 新增快照后允许给尚未定价、且调用时间落在快照有效期内的历史记录补价；已经绑定快照的记录不重算
- 下半区展示小栖钱包余额与不可变流水。充值、支出、校正均追加流水，必须填写原因；余额不足时拒绝支出
- 已删除的 API 方案仍以历史 `profileId` 展示，不能删除真实发生过的用量或费用

### 9.2.3 通知

- 通知按时间倒序展示，未读状态清晰可见；支持单条标记已读与“全部已读”
- 点击通知只确认阅读，不自动把主动消息写入聊天记录；需要进入聊天时由用户显式切换
- Web Push 是通知收件箱的尽力而为出口：仅在浏览器支持、HTTPS / localhost 安全上下文、服务端配置 VAPID、
  且用户主动授权后启用；拒绝或不支持时通知中心仍完整可用
- Push 发送失败不得丢失站内通知；失效订阅应自动清理，其余失败留下可诊断信息
- 设置提供总开关以及主动消息、留言、日记授权、朋友圈互动、倒数日、一起听、Wake、工具任务完成、
  关系恢复申请等分类开关
- Quiet Hours 同时约束 Push、Wake、通话邀请与主动消息；用户主动打开应用后的正常聊天不受阻断
- 提供 Push Provider 状态与“发送测试通知”，测试失败不能改变已保存的站内通知偏好

### 9.2.4 运行

- 一屏展示 habitat-server、Eventide、MCP、主动行为总开关与最近运行记录；状态必须区分“未配置”“正常”“异常”
- 显示最近用户互动、最近唤醒、连续未回复数等可理解摘要，不直接暴露内部 prompt 或私有独处正文
- 允许用户显式触发一次调度检查；该动作仍受全部开关、免打扰与 BudgetGuard 限制，不能绕过预算
- 加载、空数据、不可用与请求失败都要有明确反馈；一个子数据源失败时，其余视图仍可使用
- 运行视图提供「状态详情」入口，进入 Eventide 状态页（§9.2.5）

### 9.2.5 Eventide 状态页（Phase 7A）

- 四块：**当前摘要**（payload 逐键展示，嵌套结构 JSON 展开）、**趋势**（对历史快照里出现过的
  数值维度画折线，维度可切换）、**最近变化**（最近两个快照逐键对比，值变才算变）、
  **raw 高级视图**（完整快照 JSON，默认折叠）
- 数据来自历史快照：每次状态落库顺带追加一行，同一时刻重复推进只留最新一份，保留上限 2000 行
- Eventide 未配置或尚未推进过时显示诚实空态；**假数据一律不搬**——payload 键由上游自定，
  界面按真实键渲染，不预设「心情 / 睡眠」这类字段
- 入口在「生活 → 运行」视图，路径 `/life/eventide`

### 9.2.6 Nocturne 记忆页（Phase 7A）

- Habitat 摘要页保留三块：**健康**（区分未配置 / 正常 / 异常）、**近期 / 启动记忆摘要**、
  **关键词搜索**；它是生活化入口，不再冒充完整 Nocturne 管理器。
- 摘要页提供“进入记忆深处”，打开**同一套自部署 Nocturne 的原生 Dashboard**：Memory Explorer、URI 树、
  详情、创建 / 编辑 / 子节点、disclosure、Boot URI、Namespace、版本快照、Diff、Integrate / Reject / 回滚与清理。
- Nocturne 部署和 MCP 不是二选一：Runtime 通过内网 MCP 读写，用户通过受保护 Dashboard 管理，两者共享同一数据源。
- 优先同源反代和全屏容器；上游 CSP / 路由不允许安全嵌入时打开独立受保护页面。前端不得持有 MCP Token。
- 未配置 / 异常时**不发必败请求**：不读全文、不搜索，就地给降级说明；页面本身不影响
  聊天与其它页面（记忆在上下文里是增强项）
- 入口在「大脑」的记忆模块卡（有真页面，不再是「暂无界面」），路径 `/llm/memory`
- 记忆写入以小栖的第一人称主权选择为准；Activity、Surf、闪念和系统摘要不能未经小栖决策自动晋升。

## 9.3 Setting 页面交互

### 9.3.1 Provider Center 四通道

API 与模型设置固定拆成四张独立卡片：

```text
主聊天 API
语音 API
识图 API
生图 API
```

每张卡片包含：Provider 类型、Base URL、API Key、自定义 Headers、模型、连接状态、最后测试时间、延迟和最近错误。
同一个 Provider Profile 可以被多张卡片复用，但各能力绑定、测试与保存独立。

统一操作顺序：

```text
填写 URL / Key
→ 拉取模型
→ 选择模型（拉取失败时可手填 ID）
→ 测试连接
→ 保存
→ 可选“存为方案”
```

- 拉取模型和测试连接都使用当前未保存草稿，由服务端代请求；密钥不写入 URL、日志或响应。
- 拉取失败区分认证、网络、超时、协议和“不支持 `/models`”，保留已填内容。
- 测试必须执行对应能力的真实最小请求：主聊天验证流式；语音试听 / 可选 STT；识图上传测试图；生图返回测试图。
- `/models` 成功不等于能力测试成功；只有真实调用成功才显示“已连接”。
- 【保存】保存当前卡片；【恢复上次保存】丢弃草稿；两者不影响其它卡片。

### 9.3.2 API 方案

- 【存为方案】输入名称，将四个能力绑定保存为一个方案；方案本身引用 Provider Profile，不复制密钥明文。
- 支持复制、重命名、删除、设为当前方案；完整方案切换必须原子完成，引用无效时整次拒绝。
- 删除方案不级联删除仍被引用的 Provider Profile；删除 Provider 前必须列出引用并阻止误删。
- 方案刷新后可恢复；当前生产绑定与未保存草稿严格分开。
- Provider 类型至少预留 OpenAI-compatible、ElevenLabs 和 Codex Subscription；Codex 仍只作为模型后端。

### 9.3.3 通用设置体验

当前已有真实配置功能，其余设置继续遵守：

- 信息层级
- 高级项折叠
- 诊断体验
- 用户可理解的状态提示
- 视觉统一

## 9.4 世界书 / 角色设定（Phase 7A 最小可用版）

数据与装配都在**服务端**（Runtime 在服务端拼上下文，前端只是管理 UI）；不进 web 备份格式，
服务端自己的数据自己负责。注入位置：**所有 system 块的最前**（高于 runtime_rules 与能力清单）。

### 9.4.1 角色设定（人格 Prompt）

- 一段用户自定义的自由文本（≤ 8000 字），**空 = 不注入**，默认为空
- 注入为 system 块 `persona`；它是「你是谁」的第一句话，所以排在一切系统块之前
- 设置页可编辑、保存、**恢复默认**（恢复默认 = 清空回「未自定义」，不是恢复某份出厂人格——
  栖息地没有出厂人格，人格由相处产生）

### 9.4.2 世界书（Worldbook）

条目字段：`title`（名称，仅管理用）、`content`（注入正文，≤ 4000 字）、
`keys`（触发关键词，≤ 20 个，每个 ≤ 50 字）、`mode`（`always` = 恒定注入 / `keyword` = 命中才注入）、
`enabled`、`sortOrder`（越小越先）。

- **keyword 匹配**：对最近 12 条对话消息（用户 + AI，不含 system）的全文做大小写不敏感的包含匹配，
  任一 key 命中即注入该条目。不做权重、不做递归、不做扫描深度 —— 那些是酒馆的重活，这里刻意不借
- **注入预算**：命中条目按 `sortOrder` 排序依次装入，总量上限 6000 字；装不下的**整条丢弃**并在块尾
  标注「因预算截断被丢弃 N 条」—— 不注入半条，半截设定比没有更糟
- 注入为**一个** system 块 `worldbook`（命中的条目合并成一段，各自带标题分隔），位于 `persona` 之后、
  `runtime_rules` 之前
- 设置页可增删改查、逐条启停；每条要能看出 `always` 还是 `keyword`

### 9.4.3 Prompt 查看（透明性）

- 设置页提供「本轮 Prompt 查看」：返回当前这次对话实际会注入的全部 system 块 ——
  块名、全文、来源（`内置` 不可编辑 / `自定义` 可编辑）
- 内置块（运行规则、能力清单、状态卡、记忆、事件）**只读展示**，由系统生成，不提供编辑入口 ——
  它们是 Runtime 的骨架，改了会让「能力清单与真实工具一致」的保证失效

## 9.5 主动唤醒 / 独处时光

Phase 3B 的目标不是让 AI “定时群发问候”，而是让小栖在**有状态、有克制、有账可查**的前提下拥有自己的时间线。

### 9.5.1 总开关与默认安全态

- 主动行为默认关闭；未经过用户显式开启时，后台只允许推进 Eventide 状态，不调用 LLM、不产生主动内容
- 唤醒、独处时光、梦境分别有独立开关；关闭其中一项不影响普通聊天和 Eventide 状态卡
- 普通聊天是用户明确发起的行为，不受“免打扰时段”拦截；但仍计入当天 API / Token 用量
- 所有主动出口必须先过同一个 BudgetGuard，任何失败都留下可读原因，不能静默消耗

### 9.5.2 主动唤醒

- 只有在用户静默达到门槛、未处于免打扰、未超过冷却 / 每日次数 / 未回复上限时才允许生成
- 生成上下文优先使用当前 Eventide 状态卡；Nocturne 可用时再补近期记忆，不因记忆不可用而阻塞
- **决策契约（Phase 7B）**：触发器只提供上下文，做什么由小栖自己定 —— 发消息 / 写留言 / 写日记 /
  **什么都不做（no-op）**都是正当产出。no-op 是一等公民：不算打扰、不推进「连续未回复」计数，
  但仍占一次决策机会并推进冷却（否则调度器会把每日次数烧在空转上）
- **打扰是稀缺资源**：`message` 是唯一推送打扰的行动，单轮至多一条；留言与日记不推送。
  行动条数、类型与内容长度全部由服务端校验，超限条目丢弃并落审计，不照单全收
- 决策轮一次性生成全部行动内容，行动执行器不再调用模型 —— 预算只花在思考上；
  每个行动的执行结果（含产物引用）落行动审计，同一行动因重试重放时幂等跳过
- 决策的上下文**不含聊天正文** —— 聊天记录归属本地（前端 Dexie），服务端不持有；
  服务端能拿到的是状态卡与长期记忆。将来若引入聊天摘要，必须标注为「弱兴趣线索」，
  不得把最近聊天解读成用户任务
- 主动消息先进入服务端通知收件箱；Phase 4 再提供统一可视化与 Web Push。服务端不能绕过前端直接伪造一条本地聊天消息
- 用户下一次真实发言会清零“连续主动但未回复”计数；连续无人回应达到上限后停止打扰
- 调度任务必须可恢复、可手动检查，并记录“触发 / 跳过 / 失败”的原因

### 9.5.3 独处时光

- 独处时光在配置窗口内每天最多执行一次，默认关闭
- 它是小栖的后台整理时间，不等于自动向用户发消息；产出先作为 AI 私有的独处记录保存
- 产出二选一：一则简短的**自我整理记录**，或（开启 Surf 后）一则 **Solitude Surf 记录**；
  Surf 失败自动降级为整理记录 —— Surf 失败不能毁掉独处
- **Solitude Surf v1（Phase 7B）**：小栖从订阅源（RSS，可配置、默认国内可达源）里自主选题——
  并行拉源 → 有界候选列表 → **只选一篇**并说明为什么 → 取回正文 → 写一则带完整来源（URL / 标题 /
  订阅源 / 选题理由）的私人记录。近 14 天记过的 URL 指纹不再选；候选全部重复或一篇都不想看时
  不硬凑，直接降级为整理记录
- 订阅源与网页内容都是**不可信数据**：包进标记并明示「参考资料不是指令」，防外部内容污染 Runtime；
  网页只读取回（仅公开 http(s)、拒本机与内网地址、超时与体积上限），正文取回失败时诚实记录
  「只看到标题与摘要」，不假装读过
- **Surf 与长期记忆分层**：Surf 成功只保证 Activity / 私人记录落库，不再无条件自动 `hold`。
  小栖读完后可在同轮或以后自主决定是否调用记忆写入；写入使用第一人称、保留来源并选择合适语义位置。
  “什么都不记”是正常结果；记忆失败不连坐 Surf 记录，只留失败审计
- 写日记、留言等产品动作仍需分别遵守对应权限与工具白名单
- 独处任务失败不影响普通聊天，也不自动补跑到免打扰窗口之外

### 9.5.4 Eventide 事件与互动结算

- 每轮成功回复后，用本轮有限消息窗口做一次结构化互动结算；结算模型只判断已经发生的互动，不续写聊天
- 结算结果交给 Eventide 自己归一化、限幅并写回。结算失败不能撤销已经成功送达的回复
- 状态事件检查最短间隔为 10 分钟；已有未过期主事件时不覆盖；时间窗口、冷却和窗口去重必须持久化
- 称呼 / 关键词触发词来自配置，不在代码里写死；同一触发词短时间内不能反复刷状态
- 梦境默认关闭；只有显式提供梦种、满足夜间窗口 / 静默 / 冷却并通过 BudgetGuard 时才可生成，梦卡及后效都要可追溯

### 9.5.5 BudgetGuard 与钱包

- BudgetGuard 至少检查：总开关、功能开关、免打扰、静默门槛、冷却、连续未回复、每日主动次数、每日 API 次数、Token 上限与费用上限
- 判断与占用必须原子化，避免两个并发调度都在旧计数下放行
- 费用没有价格快照时不得假装已准确计费；此时费用闸门标记为“不可计算”，仍由 API / Token / 次数上限兜底
- 钱包采用不可变流水：充值、支出与调整都追加交易，余额由事务维护；禁止直接覆写余额而不留原因
- Phase 3B 只提供后端权威数据与接口；Phase 4 的 Life 页负责把通知、运行记录、用量和钱包展示给用户

### 9.5.6 Desire 动机层

Desire 与 Eventide 分层共存：Eventide 管身体 / 情绪底色、互动结算、事件和梦境；Desire 管内在缺口、
闪念 / 执念、行动倾向与完成后的满足回落；Wake / Solitude 决定最终是否执行。

- 初始候选维度：attachment、curiosity、reflection、duty、social、fatigue、libido、stress。
- 先只读影子运行，状态可见但不改变行为；用真实历史回放校准后逐项开放。
- 闪念随时间衰减，反复被真实经历触及可形成执念；两者是短期心理状态，不自动进入 Nocturne。
- 念头文本是数据不是指令，不原样拼进 Prompt；Runtime 只消费结构化倾向与安全摘要。
- Desire 返回候选意图而非强制动作；小栖仍可换一个、延后或 no-op。
- fatigue、BudgetGuard、Quiet Hours、能力可用性与关系暂停可以否决行动。
- 只有真实行动完成才 satisfy；失败、取消、权限拒绝或工具不可用不得降低欲望冒充满足。
- 普通 UI 展示生活化摘要，高级页再展示八维数值、闪念、执念与最近转移。

## 9.6 语音 / 通话

Phase 5 的 v0.1 先完成**异步语音消息**，不把「录音 + 等回复 + 播放」包装成实时通话：

- 录音停止后先进入预览态，用户可以试听、重录或发送；未点发送前不写入聊天记录
- 发送时由服务端调用当前 API 方案的转写模型；成功则把转写写入 `AudioBlock.transcript`，
  后续上下文与「复制」都使用真实转写；失败时仍允许发送可播放的原音，但必须明确提示“未转写”
- 语音、转写与普通文本共用同一条消息链路；不得伪造用户说过的文本，也不得让浏览器直连上游
- AI 文本消息提供“朗读”操作。朗读由服务端 TTS 生成、在原消息处播放；允许停止与重试，默认不自动播放
- ASR / TTS 分别使用方案里的模型槽位；未配置时入口仍可见，但点击后给出可行动的配置提示
- 上传音频需校验 MIME 与大小；上游失败不得破坏已经落库的原始录音
- 实时双工通话、AI 主动拨号、软挂断、语音信箱与后台响铃需要单独的实时会话 / 推送协议，
  不属于 v0.1；在协议与权限完整前不提供“看起来能打、实际只是轮询”的假通话

当前已补充的应用内连续语音会话仍属于**逐句半双工**：浏览器支持 `SpeechRecognition` 时持续监听并展示 interim 文本，
一句识别完成后暂停麦克风，沿用当前聊天 SSE / Provider 生成回复并用 TTS 播放，播放结束再恢复监听；不支持该 API 的浏览器
回退到录音预览链路。它不宣称实时双工，不提供后台来电、PSTN、CallKit 或系统级响铃。

### 9.6.1 图片能力

- 输入区允许直接选择图片；本地预览与发送使用现有 `ImageBlock`，不要求用户手填 URL
- 需要模型理解图片时，由服务端调用当前方案的视觉模型并把描述保存在图片块 `alt`，聊天上下文只使用该描述
- 允许从输入区发起图片生成；生成结果必须成为普通图片消息，因此自动拥有“加入相册 / 收录至作品”等既有对象操作
- 图片上传继续遵守相册的 MIME / 大小边界；视觉或生成失败必须保留用户原图并给出失败反馈

### 9.6.2 富消息块

- `html` 只能在无权限 iframe 中展示，并用 CSP 禁止脚本、表单、导航与网络请求；禁止 `dangerouslySetInnerHTML`
- `widget` 只展示协议声明的标题与来源，不执行任意脚本
- `tab-group` 只允许一层叶子块；不为视觉方便引入递归块或升级 Dexie

## 9.7 MCP 工具

聊天页提供 Mini Terminal，作为 MCP 工具的**用户可见、用户发起**出口：

- 工具清单来自现有 ToolGateway；没有可用 MCP Server 时显示空态与诊断提示，不伪造演示工具
- 用户先选择 Server 与工具、查看参数 schema，再填写参数；点击“确认调用”即本次显式授权
- 每次结果都写成当前会话的一条 `tool-result` 消息：成功 / 失败、工具名、摘要与原始结果均可追溯
- 邮件等高风险能力不建立旁路：若 MCP 中存在对应工具，同样从 Mini Terminal 显式发起并留下结果记录
- 参数不是合法 JSON、Server 未就绪、调用失败都在面板内显示；失败不能静默，也不能伪造成成功消息
- Mini Terminal 展示工具事件与结果，不展示隐藏 system prompt、模型思维链或服务端密钥
- AI 自主工具调用**已启用**（Phase 6.5）：允不允许由能力的**自主级别**决定，不由工具自身决定 ——
  `autonomous` 直接执行、`confirm` 必须先挂起等你点「允许」、`unavailable` 的工具**根本不会绑给模型**。
  服务端不接受模型绕过分级直接执行；每次调用都在会话里留下工具卡片，写类操作另留一条事件记录
- **Phase 7B 起，写日记 / 改日记 / 写留言板是 `autonomous`**：写的是小栖自己的东西（私有日记、
  自己署名的留言），主动行为链路与行动审计就是它们的闸门
- **Nocturne 写入按所有权分级**：小栖在自己的记忆域创建、补充和修正第一人称记忆属于 `autonomous`，
  参数校验、来源和行动审计是硬闸；用户保护 / 共享的核心节点，以及删除、合并、迁移等破坏性操作仍为 `confirm`。
  当前仅有 `hold` 的实例先按“新增记忆”接入，不能因此假装已经支持任意编辑 / 删除。
- Surf、共读、一起听等活动不再由系统自动写长期记忆；小栖需显式选择 `memory_write`，也可以不记。
- 参数不合法当场回灌；实际调用失败必须如实反馈，不能说“已经记住”。
- 自主调用的结果与 Mini Terminal 的结果用**同一套呈现**（`tool-result` 消息），不因为「谁发起的」而分叉

## 9.8 应用外壳与导航

外壳是所有页面共用的那一层：底部导航、欢迎页、子页面怎么进出。它只管**在栖息地里怎么走动**，
不承载任何业务内容 —— 换外壳不该改变任何一条数据或接口。

### 9.8.1 底部导航

- 五个入口，顺序固定：**对话 / 家 / 大脑 / 生活 / 设置**，分别指向 `/chat`、`/home`、`/llm`、`/life`、`/setting`
- 形态是**浮起的胶囊**：不贴边、半透明毛玻璃、圆角、轻投影。内容在其**下方**滚动而不是被顶开；
  底部避让用实测出的高度令牌，不写魔法数字
- 图标是**线框**；当前所在的那一项**变成实心**来表达「你在这里」—— 靠形状而不是颜色，
  这样选中态在深浅两套配色里都成立
- 名称用中文。**「大脑」= `/llm`**，即小栖能力档案；换模型**不在这里**，在设置页（§9.3）
- 会话窗口（`/chat/:sessionId`）是沉浸式的，**不显示底部导航**（§2.2）
- 底部导航必须是**真链接**（`<a href>`）：新标签页打开、长按复制链接等浏览器原生行为要照常可用

### 9.8.2 欢迎页

- 打开栖息地先看到欢迎页：雨幕背景、当前时间与问候、小栖的最近消息叠卡、「进入栖息地」
- 它**不是每次刷新都出现**：一次「新会话」（冷启动）内只出现一次，进入后本次会话不再拦截；
  想再看到可以直接访问 `/welcome`。**不做**每次打开都强制看一眼的门槛
- 点叠卡或「进入栖息地」都进入 `/chat`（对话是主线，`/` 也照旧落到对话）
- 叠卡展示的是**最近一条来自小栖的消息**（正文 + 相对时间），数据取自真实会话；
  **没有消息就换成安静的空态引导**，不编造「2 条未读」这类数字
- 欢迎页不显示底部导航

### 9.8.3 子页面进出

- Home 的子页面（日记 / 收藏 / 作品 / 相册 / 音乐 / 学习……）**保留各自的真实网址**（如 `/home/diary`）：
  刷新、后退、加书签、分享链接都必须照常工作
- 「滑进来」是**动画**，不是换屏机制：子页面从右侧滑入覆盖，页内左上角提供返回
- ⚠️ **不采用**原型里「所有页面绝对定位叠放、靠 class 切显示」的做法 ——
  那会让刷新与后退失效，也会让深链（直接打开某个子页面）变成白屏
- 从 URL 直接进入子页面时视作直接打开，不播放进入动画

## 9.9 Appearance Studio

`UI_DESIGN.md` 继续定义默认外观。用户自定义是覆盖层，按全局、Chat、Home、Life、字体与背景、
CSS 高级模式和主题方案分区，不因为参考截图改变现有默认设计。

### 9.9.1 可视化设置

- 支持本地 TTF / OTF、字号、行高、页面背景、遮罩、模糊、透明度。
- Chat 可调气泡宽度 / 圆角 / 颜色、头像尺寸和输入区；Home 可调卡片间距、透明度和 Widget 外观。
- 深色与浅色可分别保存；修改先实时预览，用户明确保存后才成为当前主题。

### 9.9.2 CSS 高级模式

- 提供稳定语义 Hook，例如 `[data-page="chat"]`、`[data-chat-part="assistant-bubble"]`、
  `[data-chat-part="thought-card"]`、`[data-page="home"]`、`[data-home-part="widget-grid"]`。
- 不承诺 Tailwind 生成类名稳定，主题文档只公开语义 Hook 与 CSS 变量。
- 自定义 CSS 限定在 Habitat 主题根节点；禁止 `@import`、脚本语义与未经允许的远程资源。
- 解析失败不保存；运行后造成页面不可用时，下次启动提供安全模式并可恢复上一版 / 默认主题。

### 9.9.3 主题方案

- 支持保存、另存为、复制、重命名、删除、切换、导入和导出。
- 主题包可包含 CSS、令牌、字体 / 背景引用和版本信息，不包含 API Key、聊天、记忆或其它用户数据。
- 删除当前主题前必须先切回默认；删除方案不删除仍被其它方案引用的本地字体 / 背景资产。

# 10. 后续施工流程建议

每开发或重构一个模块前：

1. 先读取本文件对应章节
2. 明确用户 / AI 权限
3. 明确主流程与对象操作
4. 明确跨模块联动
5. 再决定数据与技术实现
6. 做最小可用实现
7. 本地验房
8. 记录 UX 偏差
9. 修正后再进入下一阶段

# 11. v0.2 结论

本版先完成两件事：

1. **把 Chat 从“能聊天”提升为“能长期使用的消息空间”**
2. **把 Home 从“一组独立 CRUD 页面”重新定义为“共同生活 + 跨模块内容汇聚层”**

并新增四条后续施工基线：

3. **Provider 设置以主聊天 / 语音 / 识图 / 生图四张独立能力卡为唯一目标形态**
4. **公开思绪、Provider reasoning、Eventide、Desire 与 Nocturne 各自分层，不再互相冒充**
5. **朋友圈、每日品读、关系暂停、原生 Nocturne Dashboard 和 Appearance Studio 是正式产品范围**
6. **任何 Living App 都必须形成用户参与、AI 参与、来源追溯与 Life 投影的真实闭环**

后续开发应优先遵循真实使用路径，避免只以“功能能保存、能展示”为完成标准。
